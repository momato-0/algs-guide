# ゆるガイドのデザインの決まりごと

デザインの元は Figma Make の書き出し `D:\WebPages\figma-design`（`src/index.css` と `src/App.tsx`）。数字や形はまずそこを見て、なければこのファイルの決まりに従う。勝手に新しい見た目を発明しない。

## 1. 色と線と影
- 色は `css/base.css` の `:root` の変数だけを使う。
  - 地と線：`--paper`（地）、`--white`（カード・箱）、`--ink`（線・文字・暗い地）
  - アクセント：`--coral` / `--blue` / `--yellow` / `--green`
  - 決勝までの道：Top（上位）は赤 `--top`、Bot（下位）は青 `--bot`
  - ライトモードのみ。ダークモードは作らない。
- 線は `--ink` で太め：カードは 3px、小さい部品は 2px。
- 角の丸みは角ごとに少しずつ変えて手描きっぽくする（例 `25px 19px 29px 18px`）。4つの角が同じ丸みにはしない。
- 影はぼかさず、ずらしたベタの影にする（`3px 3px 0 var(--ink)`。深緑の地の上では `rgba(246,240,228,.24)`、窓ではコーラル）。ぼかした影やグラデーションは使わない。
- 傾けるのは ±0.25°〜2° まで。並ぶものは交互に向きを変える。スマホでは傾けない（読みやすさ優先）。
- 押したときは影がへこむ（ずれを小さくして translate する）。マウスをのせたときは少し浮くか、少し回る。

## 2. 書体
- 見出し・数字の大きい飾り：`--f-head`（Yusei Magic、weight 400 のみ。太字にしない）
- 本文・ボタン・ラベル：`--f-body`（M PLUS Rounded 1c。使える太さは 500 / 700 / 800）
- スコア・点数などの数字：`--f-num`（Chakra Petch）
- 字間の広い英字ラベル（APEX LEGENDS GLOBAL SERIES など）は、新しくは増やさない（ユーザーが保留中）。

## 3. 日本語の文字組み
- 本文の行間は 1.7〜2.0。見出しは 1.0〜1.3。2行以上ある見出しは詰めすぎない（1.05 以上）。
- 字間：Yusei Magic の大きい見出しは `letter-spacing:-.04em〜-.06em` で詰める。本文は詰めない（0）。小さいラベルは `.04em〜.08em` 開ける。
- 約物（、。！？「」）は、見出しでは `font-feature-settings:"palt"` か負の字間で詰める。本文には palt を使わない。
- 改行：見出しや短い説明は `<br>` で意味の切れ目に置き、`word-break:auto-phrase` と `text-wrap:balance` を使う。1文字だけが次の行に落ちる（例「方。」）のは直す。
- 和文と数字を混ぜるとき：数字（Chakra Petch）は漢字より下に描かれないので、そのままだと浮いて見える。`position:relative;top:.045em` くらい下げて、漢字の下にそろえる（測って決める）。
- 大きさの違う語を並べる（「決勝」＋「スタート」、「1」＋「試合目」）ときは `align-items:baseline` にする。中身が入れかわっても高さが動かないよう、見えない文字（`::before{content:"\200b"}`）を一番大きい文字の大きさで置いて、下のラインを固定する。
- 小さい語の大きさは、大きい語の 0.8〜0.92 倍。0.75 倍を下回ると「小さすぎ」と言われやすい。

### 文字組みの基本の考え方（参考：https://mmmiyama.com/typography/ の要点を、このサイト向けにまとめたもの）
- 文字は「形」として見る。数字の間隔ではなく、見た目の空きがそろって見えるかで判断する。まず全体の字間を整え（スペーシング）、それから目立つ空き（約物のまわり、「ト」「ー」のまわりなど）だけを個別に詰める（カーニング）。迷ったら目を細めてぼかして見る。
- 見た目の大きさは「漢字 ＞ かな ＞ 欧文・数字」の順に小さく見える。和文と同じ大きさに見せたい数字や英字は、少し大きくする（このサイトの「1試合目」の数字 1.4 倍は、これに当たる）。
- 単位・曜日・補助の語（月・日・時・分・(月)・pt・〜 など）は小さくして、数字を主役にする。例：「11/2<small>(月)</small> 8:00〜」。
- 行間はブラウザの初期値より広めにとる。字間・行間にゆとりのある組み方を基本にする。
- そろえ方（行頭・中央・行末）は読みやすさで選ぶ。1つのまとまりの中で、そろえ方を混ぜてガタガタにしない。
- 縦書きと横書きを組み合わせる（カードの縦書きの英字ラベルと番号など）ときは、片方の長さや高さにもう片方をそろえると、まとまって見える。
- 主役と脇役の大きさの差は、はっきりつける。中途半端な差（1.1 倍くらい）は、そろえ損ねて見える。
- 斜めや傾きは「動き」を出せるけど、読みにくくもなる。ここぞという所だけにする。
- 書体を混ぜるのは、ポイントだけ（見出しの Yusei Magic と本文の M PLUS Rounded の役割を崩さない）。
- 作るときは、まず入れる文字を大切な順に並べる。大切なものほど大きく、を基本にする。
- 1つの部品（カード・帯・窓）の中の色は、地・線・アクセントの3色までにする。

## 4. 文字の大きさの下限（PC）
- 本文・説明：15px 以上（カードの中の説明は 13px 以上）
- 補足（「20チーム・マッチポイント制」など）：14px 以上
- 英字の小ラベル：13px 以上。11px 以下は「読みにくい」と言われた
- 見出しの下の説明文：16px 以上
- スマホは、PC より 1〜2px 小さくしてもいい。ただし 11px を下回らない。

## 5. ボタンと押せる場所
- 押せる場所は 44×44px 以上（スマホでは特に）。小さい見た目のボタンでも、押せる範囲は広げる（帯や行全体を押せるようにする）。
- 帯や見出しが開け閉めのボタンなら、帯のどこを押しても反応させる（矢印や＋の丸だけにしない）。
- 大事な行動（観戦しにいく・再生など）は大きく、アイコン＋文字にする。文字だけの小さいボタンにしない。
- 押したら出るもの（選ぶリンクなど）は、押したボタンのそばに出す。画面の真ん中の窓より近い方がいい。外を押す・Esc で閉じる。
- 窓は `<dialog>` の `showModal()` で開いて、後ろのページはスクロールさせない（`:root:has(... :modal){overflow:hidden}`）。

### 読みやすさ・さわりやすさの決まり（参考：design-taste スキル https://github.com/h3nryprod01/design-taste の考え方のうち、このサイトとぶつからないもの）
- 文字と背景の明るさの差（コントラスト）：本文は 4.5:1 以上、大きい文字（18px 以上、または 14px 以上の太字）は 3:1 以上。薄い灰色の文字が足りなくなりやすいので、色を足したら測る。足りなければ `--ink` に寄せる。
- ボタンの状態は、ふつう・マウスをのせたとき・キーボードで選んだとき（`:focus-visible`）・押したとき・押せないとき、まで作る。キーボードで選んだときの枠は消さない（`outline:none` にするなら、代わりの見た目を必ず作る）。
- 動き：部品の動きは 0.3 秒以内。出るとき・消えるときは「すっと始まって、ゆっくり止まる」動き（ease-out。例 `cubic-bezier(.23,1,.32,1)`）にする。最初がゆっくりの ease-in は使わない。0 から大きくするのではなく、0.6〜0.95 くらいから。動かすのは `transform` / `translate` / `rotate` / `scale` / `opacity` を基本にして、`top` や `width` は動かさない。
- キーボードで選んだときの枠は、地の色で見えなくならない色にする（ふだんはコーラル。コーラルの地の上（01 のカード）では深緑）。
- 閉じている開け閉めの中身や、隠れているパネルには `inert` をつけて、キーボードで選べないようにする。
- 色は `--coral` を文字に使うと薄すぎる。白い地にコーラルの字・コーラルの地に白い字は `--coral-ink` を使う。
- 動きの曲線は `var(--ease-out)` を使う。スライド（動画）の中の動きは「中身」なので、この決まりの外。
- 動きを減らす設定（`prefers-reduced-motion`）の人には、動きを止める（`css/base.css` の最後にまとめてある）。
- 窓は `<dialog>`、ボタンのそばに出す小さいパネルはブラウザの部品（`hidden` の切りかえ、使えるならポップオーバー）を使う。z-index は大きすぎる数（999 など）にしない。
- 大きい見出しの字間は、詰めても -0.04em くらいまで。それ以上詰めて、文字同士がくっついていないか見る。
- ボタンの文字は短くていい（「ひらく」「見る」など）。何が起きるか、まわりの文脈でわかればいい。

## 6. 配置
- 余白は 8 の倍数を基本にする（8 / 12 / 16 / 24 / 32 / 48）。カードの中の余白は PC 24〜34px、スマホ 17〜22px。
- PC のナビは、上の真ん中に浮かぶクリーム色のバー（参考：https://games.parco.jp/page/constance/）。スマホは右上の四角いボタンと、左のふちがヨレた紙のパネル。
- セクションの境目は、まっすぐな線よりギザギザや波線にする。

## 7. 作業の進め方
- ファイルの分け方：共通は `css/base.css`・`js/site.js`、セクションは `css/<id>.css`・`js/<id>.js`。セクションのセレクタは全部 `#<id>` から始める。
- 直したら、PC（約 1024px）とスマホ（375px）の両方をブラウザで見てから報告する。見られなかったところは、見ていないと書く。
- ユーザーは自分でも CSS を直す。ファイルが変わっていたら、それを今の状態として受け取る。
- 文言（コピー）はユーザーが決める。仮の文言には「仮」とコメントを書いておく。

## 8. これまでの指摘（同じことを言わせない）
- PC で小さくて読めなかった文字：「APEX LEGENDS GLOBAL SERIES」、見出しの下の説明文、「20チーム・マッチポイント制」 → 4章の下限を守る
- 「観戦しにいく」が小さすぎた → 大きいテレビのアイコン（中に LIVE）にして、押すとまわりに3つのリンクが出る形にした
- タイトルの「決勝」が大きすぎ、「スタート」が小さすぎた → 1倍と 0.92 倍で落ち着いた
- 数字が漢字より浮いて見えた → 3章のとおり下げてそろえる
- 50pt の棒の頭とタイトルが重なった → 重なりは測って、ずらす量（px）を報告する
- 手作り感は「全部同じ角丸・グラデーション・ぼかした影」をやめることで出る
